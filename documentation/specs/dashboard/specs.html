Dashboard Specification

Updated to match the current implementation in apps/web/src/pages/dashboard.

Purpose

The dashboard is a thin React front-end that exposes the two import flows already present in the backend and reads two projection views: spend mix and merchant transactions.

Current Layout

Header area
  -> Receipt upload card
  -> Bank statement upload card
  -> Static summary panel

Data area
  -> Spend mix pie chart
  -> Merchant transactions table

Backend Dependencies

Frontend action Endpoint Method
Upload one receipt /scan/receipts POST
Upload one bank statement /bank/statements POST
Load spend mix /projection/charts/spend-mix GET
Load merchant transactions /projection/merchant-transactions GET

Implemented Views

View Current behavior
Receipt upload card Accepts one PNG or JPEG file at a time and shows upload status.
Bank upload card Accepts one CSV file at a time and shows import status.
Spend mix card Renders a Recharts pie chart plus a legend from the spend-mix API response.
Merchant transactions card Renders a compact table with date, merchant, label, match status, and formatted amount.
Summary panel Displays static mock values; it is not currently wired to backend data.

What The Dashboard Does Not Do Yet

  • No forecast charts or forecast-by-label view.
  • No filters for date, label, currency, or match status.
  • No labeling workflow or correction workflow.
  • No projection review or correction queue.
  • No reseller or VAT-centric timeline exploration.

Client Behavior

  • On first render, the page fetches spend mix and merchant transactions in parallel.
  • After a successful receipt or bank upload, the page reloads those same two datasets.
  • If a load fails, the page currently clears both datasets rather than showing a dedicated error state.
