Scan Module Specification

Updated to match the current implementation in apps/scan/src.

Purpose

The scan module accepts one receipt image upload, normalizes it, extracts OCR text and structured fields, persists the canonical receipt, and triggers projection rebuild synchronously. It does not own matching rules, projections, labels, or dashboard reads.

HTTP Contract

Route Method Input Behavior
/scan/receipts POST Multipart form-data with one receipt file. Accepts image/png and image/jpeg. Returns 400 for missing or unsupported files, 422 when extraction fails validation, and 200 with the saved receipt otherwise.

Processing Flow

User upload
  -> Validate multipart request and MIME type
  -> Normalize image and compute content hash
  -> Run OCR on normalized image
  -> Extract structured receipt fields
  -> Reject the receipt if required fields are missing
  -> Persist canonical receipt in PostgreSQL
  -> Reuse existing receipt when content hash already exists
  -> Trigger projection rebuild synchronously

Extracted Field Contract

Field Status Notes
merchant Required Missing value produces merchant_not_found.
vatId Required Missing value produces vat_id_not_found.
purchasedOn Required Stored as day precision in the canonical receipt row.
totalAmount Required Missing value produces total_amount_not_found.
currency Required Missing value produces currency_not_found.
vatAmount Optional warning Missing value produces vat_amount_not_found.
paymentMethod Optional warning Missing value produces payment_method_not_found.
cardLast4 Optional warning Missing value produces card_last4_not_found.
items Optional warning Missing items produce items_not_found.

Persistence

Canonical receipts are stored in PostgreSQL table receipt. The current row stores:

  • source image path and normalized image path
  • content hash used for deduplication
  • OCR raw text
  • projected top-level fields such as merchant, VAT ID, date, amount, currency, payment method, and card suffix
  • the full extractedFields payload as JSON

When the same image hash is imported again, the existing receipt is returned and no new row is inserted.

Implementation Notes

  • Image normalization is handled by sharp.
  • OCR is handled by tesseract.js.
  • Module-to-module orchestration is synchronous and in-process through the projection handler.
  • There is no user correction flow, manual override flow, or async worker pipeline in the current implementation.
