Bank Module Specification

Updated to match the current implementation in apps/bank/src.

Purpose

The bank module imports one statement CSV, validates and normalizes rows, persists a canonical statement import plus bank transactions, and triggers projection rebuild synchronously. It does not handle OCR, dashboard rendering, or forecasting.

HTTP Contract

Route Method Input Behavior
/bank/statements POST Multipart form-data with one statement file. Requires a .csv filename and one of the accepted CSV-like MIME types. Returns 400 for invalid input, 422 for rejected statement content, and 200 with the imported statement otherwise.

CSV Contract

The parser expects this exact header:

date,description,amount_eur,balance_eur,currency
Column Meaning Validation
date Posting date Must be YYYY-MM-DD.
description Raw bank description Must be non-empty.
amount_eur Signed transaction amount Must parse as decimal.
balance_eur Running balance Must parse as decimal.
currency Currency code Must be a supported ISO-style code.

Processing Flow

User upload
  -> Validate multipart request, file extension, and MIME type
  -> Store raw CSV and compute source file hash
  -> Read stored CSV content
  -> Parse records, including quoted values
  -> Reject when header is unsupported
  -> Normalize valid rows into canonical bank transactions
  -> Keep malformed rows with explicit error codes
  -> Persist statement import and transactions
  -> Reuse existing persisted import when source file hash already exists
  -> Trigger projection rebuild only for non-duplicate imports with transactions

Persistence

Table Role Current notes
statement_import One imported CSV file Stores statement_import_id, source_file, source_file_hash, import_status, and imported_at.
bank_transaction Normalized ledger rows Stores raw and normalized descriptions, signed amount, currency, posting date, and original source row number.

The only persisted import statuses today are valid and malformed. Duplicate detection is a runtime behavior based on source_file_hash; there is no persisted duplicate enum value.

Malformed and Duplicate Behavior

  • Malformed rows are returned as structured row-level errors instead of being silently dropped.
  • A file whose hash already exists returns the previously persisted import and transactions.
  • Duplicate imports do not trigger projection rebuild again.
  • Unsupported headers raise statement_rejected with invalid_statement_header.
